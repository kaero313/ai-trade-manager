# 외과적 패치

비용이 적으면 먼저 실패를 재현한다. 재현이 비싸면 확보 가능한 가장 강한 증거를 남긴다.

- 증상에서 책임 있는 메커니즘까지 추적한다. 원인을 모르면 `systematic-debugging`을 먼저 적용한다.
- 잘못된 동작을 소유한 가장 좁은 계층만 바꾼다.
- 무관한 동작과 사용자의 기존 변경을 보존한다.
- 수정 범위 밖의 정리·이름 변경·추상화를 하지 않는다.
- 작업과 관련된 회귀 증명만 추가한다.

실주문·청산·거래 모드 전환·관리자 인증 경계를 건드리면 `reviewer` 역할의 검토를 받는다.

집중 증명과 가장 가까운 게이트를 돌린다. 실패가 고쳐지고 회귀 증명이 통과하면 멈춘다.
